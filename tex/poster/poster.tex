\kicker{The four travel poorly}
\sectionhead{Classical signals}

{\body
Google SRE's four --- latency, traffic, errors, saturation --- assume a
stateless request/response service. On shared GPU clusters:
}

\vspace{0.20in}
{\body
{\bfseries\color{navy}Latency} has token, batch, epoch, \emph{and queue}
meanings. Submit-to-start often dominates. HTTP p99 never sees it.

\vspace{0.16in}
{\bfseries\color{navy}Traffic} as QPS is undefined for training.
Tokens/s and active jobs are different loads.

\vspace{0.16in}
{\bfseries\color{navy}Errors} as HTTP 5xx miss silent quality failure
(200 + a bad output) and OOM / throttle restarts.

\vspace{0.16in}
{\bfseries\color{navy}Saturation} as \texttt{nvidia-smi} utilization is
time-busy, not useful compute. Memory-bound kernels, thermal trips, and
NCCL stragglers can all look fully utilized.
}

\vspace{0.20in}
{\captiontext
Mechanistic failure modes. The Slurm DCGM slice is idle T4 queue-wait
(utilization $=0$); a util--goodput correlation is undefined on that trace.}
\end{minipage}%

\begin{minipage}[t]{0.39\textwidth}
\kicker{Scope and limitations}
\sectionhead{Limits}

{\body
\begin{itemize}
  \item One signal measured (QWR). GCE, HPH, SAI, OQC are candidates only.
  \item Small test set: $\sim$8 positives in 111 Slurm test jobs.
  \item DCGM columns idle on T4 queue-wait trace; GCE/HPH cannot be computed from it.
  \item EKS and Slurm use different ``long wait'' labels; results are not pooled.
\end{itemize}
}
